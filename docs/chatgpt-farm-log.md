# ChatGPTから農作業日誌へ記録する手順

最終確認: 2026-11-03
対象: GitHub `hirotodesuyo/farm-log` / Vercel プロジェクト `manifest`
利用者向けアプリ: https://manifest-olive.vercel.app/

> 目的: ChatGPTのチャットが変わっても、「今日の作業を記録して」と依頼されたら、接続手段を調べて実際の保存結果まで確認するための手順書。これは記録方法の説明であり、ChatGPTのすべての会話に接続権限を付与するものではない。

## 基本方針

- ユーザーの発話に基づく**実際に行った作業だけ**を記録する。農薬の希釈倍率、場所、量、終了時刻など不明な欄は推定せず空欄または「未確認」と明記。
- 「記録した」と言うのは**サーバーから成功応答を受けた後だけ**。接続不可なら登録していないと明言する。
- 同じ作業を再送するときは、**同じ `key`** を使い二重登録を防ぐ。
- 時差に注意。日付はユーザーの**日本時間（Asia/Tokyo）**の指定を優先。相対日付は会話時点を確認する。
- 日誌データはVercel Blobの `farm-log/entries.json` に保存。別チャットに切り替わること自体でデータは削除されない。

## 実装・接続先

- GitHub: `hirotodesuyo/farm-log` （main）
- Vercel project: `manifest`
- 保存API（既存実装）: `api/assistant-entry.js`
- アプリ同期API（別経路）: `api/entries.js`
- `assistant-entry` は **GET** のみ、かつ `VERCEL_ENV=production` で `Host === VERCEL_URL` のリクエストを受け付ける。**アプリの固定ドメイン `manifest-olive.vercel.app` は、このAPIへの書き込み用としては利用しない**。
- 最新のProductionデプロイホストはVercelの `get_project` または `list_deployments` でその都度取得すること（デプロイごとに変わる）。古いホストを固定しない。
- ChatGPTのVercelコネクタで `web_fetch_vercel_url` が利用可能なら、その認証付き取得を使って本番デプロイの完全URLを呼ぶ。利用できなければ別の承認済み手段を調べる。認証制限を勝手に解除しない。

## 一件の記録手順

1. 会話から日付・作物・場所・作業種別・詳細・数量・備考を抽出。あいまいな情報は作らない。
2. 必要ならGitHubで `api/assistant-entry.js` とVercelの最新のProductionデプロイを確認し、接続先の変更を検知する。
3. 日本語をURLエンコードして、以下のクエリをデプロイホストの `/api/assistant-entry` に渡す。

| パラメータ | 必須 | 内容 |
| --- | --- | --- |
| `date` | 必須 | `YYYY-MM-DD` |
| `type` | 推奨 | `収穫` / `灌水` / `液肥` / `防除` / `生育` / `その他` / `予定` |
| `crop` | 推奨 | 例：いちご、越後姫 |
| `place` | 任意 | 例：2号ハウス |
| `detail` | 推奨 | 作業の内容 |
| `amount` | 任意 | 例：散布液150L |
| `subamount` | 任意 | 補助数量 |
| `note` | 任意 | 詳細な補足、不明点 |
| `time` | 任意 | `HH:MM` |
| `key` | 強く推奨 | 一作業を識別する安定した任意文字列（最大160文字）。再試行は同じキーを使う |

4. レスポンス本文が `ok: true` であることを**必ず確認**する。`changed: true` は新規保存、`changed: false` は既存記録と一致またはキー重複。`entry` と `count` を確認する。
5. エラーなら**未保存**と報告して原因を調べる。二重登録を避けるため、再試行には同じ `key` を使用する。
6. 保存後はユーザーに日付、場所、作業、重要数量、未確認事項と保存結果を伝える。

## トラブルシューティング

- Vercel認証へのリダイレクト（302）: 非認証の直接アクセスを使っていないか確認。権限のあるVercelコネクタの `web_fetch_vercel_url` を検討。
- アプリからの403: このAPIにはProductionのデプロイ固有ホストを使用する必要がある。固定ドメインやPreviewでは受け付けない。
- `api/entries.js` の401/503: 別API。環境変数 `FARM_LOG_SYNC_KEY` を確認。ただし**キーの値をGitHubやチャットへ貼らない**。
- APIにアクセスする手段が会話ごとに異なることがある。「別チャットだからできない」と即断せず、接続されているVercel/GitHubの権限・最新実装を確認。権限がなければ保存できない旨を説明する。
- **重要なセキュリティ注意**: 現状の `assistant-entry` はGETで追加操作を行い、アプリ側の同期キー認証とは別方式。共有リンクは外部に配らず、記録内容に秘密情報を含めない。APIの認証強化は別途検討する。

## 自動化での注意

このドキュメントを保存しても、すべてのチャットへ自動的にツールが接続されるわけではない。実際に呼び出せるVercel/GitHubコネクタがある場合に手順を実行し、必ず保存成功を検証する。
